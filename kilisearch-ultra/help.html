Using Killi

Killi is a search box that talks back. Type or say what you're looking for, and it searches, answers, and remembers — no separate "search" and "chat" screens to switch between.

Overview

Everything happens in one screen: a search bar at the bottom, a conversation above it, and a row of quick-start topics. Type a question the way you'd ask a person, or tap a topic chip to jump straight in.

Killi doesn't need an internet connection to feel fast, but it does need one to answer — it's not a general AI chatbot. It searches the exact information the people running this app gave it, and follows up conversationally on top of that.

Searching & chatting

Type into the search bar and press the arrow, or hit Enter. Killi looks for the closest match — including matches for words you've slightly misspelled or typed differently (it understands "colour" and "color," or "recieve" and "receive," as the same word).

If your question is broad, Killi asks a short follow-up instead of guessing. Answer that, and it narrows down to the right result — the same way you'd clarify with a person behind a counter.

Once you get an answer, you can keep going in the same thread: "what about the weekend hours?" or "is that the same for the downtown branch?" both refer back to what you just asked, without you having to repeat yourself.

Sectors & chips

The row of rounded buttons above the search bar are shortcuts into the most common topics. Tapping one fills the search bar with that topic — it doesn't submit automatically, so you can adjust the wording first if you want.

Voice & attachments

Where the microphone button is present, tap it and speak your question instead of typing it — useful one-handed or on the move.

Some Killi apps also let you attach a photo or PDF alongside your question (for example, a picture of a product or a receipt). Look for the paperclip icon next to the search bar — it only appears where the app you're using has turned attachments on.

Installing the app

Killi can be installed like a native app on your phone, tablet, or computer — no app store required.

  1. 1

    Look for the install icon (a downward arrow) near the top-right of the screen. It only appears once your browser decides the page is installable — this can take a moment on first visit.

  2. 2

    Tap it, then confirm. Your browser shows a native "Add to Home Screen" / "Install app" prompt — accept it.

  3. 3

    Open it from your home screen or app list from then on. It launches in its own window, full-screen, with no browser address bar.

Long-press (or right-click) the installed icon to jump straight into one of the top topics, the same way the topic chips work inside the app.

Not every deployment offers installation — some sites embed Killi inside a larger page, where the surrounding site handles its own "app" experience instead.

Working offline

Once installed, Killi keeps its own look and feel available even with no signal — the interface itself still opens. Answers still require a connection, though: if you're fully offline when you open the app, you'll see a simple, unbranded "you're offline" page instead of a stale answer that might be wrong.

Dark mode

Tap the moon icon in the header to switch between light and dark. Your choice is remembered the next time you open the app.

Locked apps

Some Killi apps are password-protected — you'll see a simple unlock screen before anything else loads. If you're already mid-conversation when a session expires, Killi won't lose your place: it shows an inline prompt right in the chat, and picks the conversation back up exactly where you left off once you re-enter the password.

Common questions

Killi gave me an answer that seems out of date.

Killi only knows what the organization running it has told it. If something's changed recently, let them know — there's usually a way to reach them referenced in the answer itself.

Can I use Killi in another language?

That depends on the content the organization has provided — Killi searches in whatever language its information was written in.

Is my conversation private?

Killi remembers your current conversation so follow-up questions make sense, and anonymized questions may be logged to help the organization improve their answers over time. It doesn't ask for personal information unless a specific form on the site requests it.

Running Killi

The admin area is where you connect your information, control who can manage it, and shape what the people using your Killi app can see and do.

Overview

Everything an admin needs lives under /admin: a guided setup wizard for first-time configuration, and a single connections page for ongoing management of data sources, admin accounts, licensing, and app access. Records, FAQ promotion, and backups each have their own dedicated screen linked from there.

Guided setup

The first admin to visit is walked through a three-step wizard:

  1. 1

    License activation. Enter a license key to unlock Standard or Ultra features, or skip to continue on Free.

  2. 2

    App password. Optionally set a password that visitors must enter before they can use the search/chat app at all. Skippable.

  3. 3

    Summary. Confirms what's configured and marks setup complete.

Once setup is marked complete, editors (see below) are redirected straight past the wizard to the main connections page — only an owner can re-enter it.

Admin accounts & roles

Killi supports multiple admin logins, each assigned one of two roles:

Owner

Full control: manage other admin accounts, licensing, database connections, backups and restores, and every editor capability below.

Editor

Day-to-day content work: manage records, promote FAQs, adjust branding. Cannot create/remove admins, change licensing, manage database connections, or restore a backup.

Manage accounts from the Admin accounts card on the connections page — owners can add a new admin, assign a role, or remove an account.

Login security

Every admin form submission (login, setup, connections, records, FAQ, backup) is protected by a per-session CSRF token, checked before any action runs.

Repeated failed logins from the same address are rate-limited: five failed attempts locks that address out of the login form for 15 minutes, protecting against password guessing.

App access

The App access card lets an owner turn the visitor-facing password lock on or off, and change the password, independent of the setup wizard.

Data sources Standard+

Killi can search and answer from several kinds of data, configured from the Database connections card:

Local content

The built-in JSON content you write directly — always available, no license required beyond Free's baseline search.

Imported files Ultra

Upload a CSV or JSON export from another system; Killi detects its structure automatically and folds it into search.

Cached database snapshot Ultra

Connect to a real MySQL/PostgreSQL database and pull a one-time copy in. Fast, but won't reflect later changes until refreshed.

Live database query Ultra

Connect live — every search reads the database fresh. Optionally mark the connection writable so the Records screen can create, edit, and delete real rows, not just read them.

Use Test connection to verify credentials, Preview to see a sample of what will be searchable before committing, then Publish to make it live.

Records (CRUD) Standard+

The Records screen is a straightforward create/edit/delete table over whichever data source you select — local content, an import, or a writable live database. Search and pagination work the same way regardless of where the data actually lives. Read-only sources (a non-writable live connection) hide the create/edit/delete controls automatically rather than letting you attempt a change that can't be saved.

FAQ promotion

Killi quietly logs the questions people actually ask. The FAQ screen surfaces the most frequent ones so you can turn a common question into an official, curated answer with one click — turning real usage into better answers over time.

Backup & restore Owner only

Create a backup at any time to download a zip of your content and configuration (credentials and secrets are never included). Restoring validates every file inside the zip before touching anything live — unrecognized paths or malformed content are silently skipped rather than applied.

Branding

Product name, tagline, color palette, and search placeholder text are all configurable, and apply immediately across the chat app, its installed-app icon, and its splash colors. Ultra removes the "Powered by Killi" attribution line for a fully white-labeled look.

Building on Killi

Killi is plain PHP 8 and vanilla JavaScript — no framework, no build step, no required database. It runs on any PHP host and scales up to real MySQL/PostgreSQL only when you choose to.

Overview

The codebase is organized around four pillars — Search, Conversation, Memory, and CRUD — sitting on top of a swappable storage layer. Everything is namespaced under Killi\Core and Killi\Adapters, and wired together through a single bootstrap.php that every entry point requires.

Project structure

kilisearch-ultra/ bootstrap.php # global killi_* helpers, feature gating, wiring core/ # SearchEngine, ConversationEngine, MemoryEngine, # CrudEngine, ConnectionManager, DbAdapter, ... adapters/ # StorageInterface + JsonAdapter admin/ # connections.php, setup.php, records.php, faq.php, backup.php api/ # records.php, export.php, app_auth.php (JSON endpoints) portal/ # index.php (chat UI), manifest.php, icon.php, sw.js, offline.html assets/ # css/killi.css, js/killi.js config/ # packages.json, branding, data_sources.json data/ # content JSON, admins.json, query_log.json, audit_log.json examples/ # host-app-demo.php

Storage & data sources

All four pillars talk to data through StorageInterface, never a concrete class — this is what lets the same CrudEngine operate identically over local JSON or a live production database.

JsonAdapter

Reads/writes a local JSON file. Backs local content and both imported and cached-snapshot sources.

DbAdapter

all() queries the live database fresh on every call. save()/delete() only perform real writes when the source is marked writable, via ConnectionManager.

ConnectionManager holds PDO connection handling plus insertRow(), updateRow(), and deleteRow() for live writes, and DataSourceEngine/SchemaDetector handle picking the active source and inferring structure from an imported CSV/JSON file.

The four pillars

Search

SearchEngine — fuzzy matching (Levenshtein distance) and phonetic matching (Soundex), a relevance gate to avoid forcing a bad match, and ranked results.

Conversation

ConversationEngine — rule-based dialogue and clarifying follow-ups. No LLM or external AI call is involved anywhere in Killi.

Memory

MemoryEngine — Jaccard token-overlap for recalling relevant past Q&A, plus query logging that feeds the admin FAQ-promotion screen.

CRUD

CrudEngine — validated create/update/delete over any StorageInterface (required title, email-format checks, status enums), with search and pagination built in.

API endpoints

The chat frontend and admin screens both talk to a small set of JSON endpoints under /api:

  • api/records.php — search/create/update/delete against the active CRUD source, feature-gated the same way as the admin UI
  • api/export.php — export the active source's records
  • api/app_auth.php — backs the inline mid-chat unlock prompt, so a session expiring mid-conversation doesn't drop the visitor back to a blank login screen

Host-app integration

Killi can run standalone or be embedded inside a larger application. A host app authenticates the visitor itself and hands identity to Killi by setting $_SESSION['killi_host_user'] before Killi's bootstrap runs — see examples/host-app-demo.php for the reference pattern.

Pass ?embed=1 when linking or iframing portal/index.php from a host app: it suppresses the PWA manifest, install prompt, and service worker registration, since the host app owns its own "installable app" story.

Security model

  • CSRF — every state-changing admin form is protected by a per-session token, checked server-side before the action runs.
  • Login rate-limiting — 5 failed attempts locks an IP out of the admin login form for 15 minutes.
  • Identifier validation — live-query writes reverse-map canonical fields to real column/table names through ConnectionManager::assertIdentifier() (/^[A-Za-z_][A-Za-z0-9_]*$/), rejecting anything that isn't a plain identifier before it ever reaches SQL — defense-in-depth against injection via a malicious configured column name.
  • Backup restore allowlist — a restored zip is only ever applied entry-by-entry after validating each path is a flat data/*.json or config/*.json file with genuinely parseable JSON content; anything else (path traversal, wrong extension, malformed JSON) is silently skipped.
  • Role gating — owner-only actions (admin management, licensing, database connections, backup/restore) are checked both in the UI (hidden controls) and again server-side on the handling endpoint.

PWA internals

portal/manifest.php generates the web app manifest dynamically from the active branding config (name, colors, icon) and includes shortcuts into the top sectors. portal/icon.php renders the app icon on the fly with GD — no bundled font or image asset required. portal/sw.js is a minimal service worker: it caches only the static shell (CSS, JS, the offline fallback page) and deliberately never caches index.php or any /api/* response, since those carry live session, branding, and search state that a stale cached copy would get wrong. Navigation requests use a network-first strategy with cache: 'no-store', falling back to offline.html only when the network is genuinely unreachable.
